# Лабораторная 5, пункт 3 — относительная оценка трудоёмкости

Дата оценки: **12.11.2026**. Проект: **ЮУрГУ.Пары**. Основной [GitHub Project № 1](https://github.com/users/unlaesh/projects/1).

Документ описывает метод, исходные допущения и значения поля Estimate. Источник чисел — [estimates-step3.json](estimates-step3.json). Все 58 значений записаны в GitHub и проверены повторной выгрузкой 12.11.2026 в 12:57 UTC. Публикация локальной документации выполняется пользователем отдельно.

## Метод и единица измерения

Используется **индивидуальная экспертная относительная оценка** по описаниям задач, границам работы и критериям приёмки в [бэклоге проекта](https://github.com/users/unlaesh/projects/1). Сначала выбран эталон, затем остальные задачи сопоставлены с ним по объёму результата, числу сценариев, сложности обработки ошибок и необходимым проверкам. Обоснование и главный риск каждой оценки приведены ниже.

Индивидуальный метод выбран для учебного эксперимента, который выполняется одним автором. Вместо командной сессии Planning Poker применяются единый эталон, сопоставление задач и повторная проверка крайних оценок; отдельное голосование участников не проводилось.

**Estimate измеряется в командных человеко-часах.** Это сумма активного труда участников команды: уточнение, разработка или подготовка материала, проверка результата, необходимая документация и ревью. Четыре человеко-часа могут означать, например, три часа исполнителя и час проверяющего; это не обязательно четыре часа календарной длительности.

Оценивается полный объём каждой карточки по её критериям. Зависимости считаются готовыми и оцениваются в своих карточках: настройка базы данных не добавляется повторно к каждому обработчику бота, а разработка функций — к их приёмочному тестированию. В технические карточки включены локальные проверки изменяемой логики; отдельные задачи интеграционной, системной, нагрузочной и пользовательской проверки покрывают свои наборы сценариев без повторного включения той же работы. Существенные изменения по обнаруженным дефектам потребуют отдельного учёта.

Пассивное ожидание DNS, ответов пользователей, накопления резервных копий или недельного журнала уведомлений не считается непрерывной работой человека. Оно влияет на календарную длительность и зависимости, которые ещё предстоит рассчитать.

Подробный расчёт приведён в [Development](https://github.com/unlaesh/project/wiki/Development).

Эти две оценки получены прямым расчётом объёма событий. Их отношение к эталону показано для сопоставления, а не вместо расчёта. **39 чел.-ч уже входят в общие суммы ниже** и учитываются внутри доступного времени участников; повторно прибавлять их к разработке нельзя. Совмещение ролей одним человеком не увеличивает число участников.

Для [#57 / 6.3.3](https://github.com/unlaesh/project/issues/57) Estimate = **8 командных чел.-ч**: подготовка 1,5 ч, модерация 2,5 ч, анализ 2 ч, протокол 2 ч. Дополнительно отдельно предусмотрено **2,5 чел.-ч внешних бета-тестировщиков**. Это время пользователей не включено в Estimate #57 и командный итог 496 ч. При оценке общей потребности в участии исследования необходимо учитывать обе величины, не смешивая состав ресурсов.

## Проверка результата и дальнейшие шаги

Повторная выгрузка [GitHub Project № 1](https://github.com/users/unlaesh/projects/1) подтвердила точное совпадение всех 58 значений Estimate с [машиночитаемым набором](estimates-step3.json). Номера карточек и идентификаторы элементов сверены; прочие поля всех 60 карточек не изменились. Оценки исключённых #58 и #59 остались незаполненными. Эти результаты относятся к указанному моменту проверки и не обновляются автоматически.

Оценки первого майлстоуна уточнены отдельно в [пункте 4 — PERT](pert-step4.md). В [пункте 5](estimation-step5.md) E перенесены в GitHub; исходные оценки этого документа сохранены как база сравнения. Следующие расчёты обоснуют общий резерв, зададут доступность участников и позволят проверить календарный план. Фактические трудозатраты фиксируются только после выполнения работ и используются отдельно для калибровки будущих оценок.
