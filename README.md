# ЮУрГУ.Пары

Учебный проект Telegram-бота с расписанием пар для студентов ЮУрГУ. Планируемые функции: просмотр расписания, заметки к занятиям и напоминания о следующей паре.

> **Статус:** подготовлен HTTP-каркас; пользовательские функции MVP в разработке.
> **Сроки проекта:** 21.09.2026 – 20.12.2026.

## Зачем

Проект решает потребность студента быстро узнать следующую пару и аудиторию в привычном мессенджере, а также хранить домашние задания рядом с расписанием. Исходный сценарий — открыть расписание на online.susu.ru и найти нужный день; доступность данных и условия авторизации ещё предстоит исследовать.

Планируемое решение переносит просмотр расписания в Telegram: заметки будут привязаны к конкретной паре, а напоминания помогут заранее подготовиться к занятию.

## Планируемые возможности

После реализации пользователь сможет указать свою группу и пользоваться следующими функциями:

| Возможность | Этап |
| --- | --- |
| Расписание на сегодня, завтра и неделю одной командой: название пары, время, аудитория, преподаватель | MVP |
| Текстовые заметки к парам (домашнее задание, записанные текстом дедлайны), видимые вместе с расписанием | релиз 1.1 |
| Уведомление о следующей паре и аудитории за выбранное время до начала | релиз 1.2 |
| Уведомления об изменениях в расписании | релиз 1.2 |

В учебной версии все перечисленные функции бесплатны. Автоматические напоминания по дедлайнам — идея дальнейшего развития, не входящая в требования релиза 1.2.

Роли в системе:

| Роль | Что делает |
| --- | --- |
| Пользователь | Смотрит расписание, ведёт заметки к парам, настраивает уведомления |
| Администратор | Просматривает пользователей |
| Сервис | Парсит расписание с сайта ЮУрГУ |

## Технологии

В текущем каркасе используются Python 3.12+, FastAPI, Uvicorn и Pydantic Settings; для проверок — Pytest, HTTPX и Ruff.

Целевой стек остальных компонентов:

| Задача | Технология |
| --- | --- |
| Telegram-бот | aiogram |
| База данных | PostgreSQL |
| Миграции базы данных | Alembic |
| Парсинг расписания | Playwright, BeautifulSoup |
| Развёртывание | Docker Compose, Nginx, VPS |

Эти компоненты пока не реализованы. Согласно [целевой архитектуре](https://github.com/unlaesh/project/wiki/Architecture), обмен данными между сервисами будет идти через PostgreSQL; брокер сообщений не предусмотрен.

## Запуск текущего HTTP-каркаса

Нужен Python 3.12 или новее.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env          # локальные настройки; .env не коммитится

python -m pary.api            # HTTP-сервис на http://127.0.0.1:8000
curl http://127.0.0.1:8000/health
```

Для `/health` токен Telegram и база данных не нужны. Команда запускает HTTP-сервис; обработка команд Telegram ещё не реализована.

Проверки CI (GitHub Actions) настроены для push в любую ветку и pull request в `main`:

```bash
ruff check .
ruff format --check .
pytest
```

## План работ

30 дней на MVP и дополнительные 10 дней на заметки — исходные оценки этапов из [Concept](https://github.com/unlaesh/project/wiki/Concept). Они уточняются по задачам WBS и не отражают фактическую длительность выполненных работ.

| Этап | Исходный ориентир |
| --- | --- |
| MVP: парсер расписания и отображение студентам | 30 дней |
| Заметки к парам | +10 дней после MVP |
| Бесплатные уведомления, тестирование на пользователях, доработка | оставшееся время до 20.12.2026 |

Обязательная часть — MVP. Заметки, уведомления и панель администратора реализуются по мере наличия времени: срок зафиксирован, гибким остаётся только объём.

## Цель проекта

К 20 декабря 2026 года выпустить обязательный MVP Telegram-бота с выбором группы и просмотром расписания ЮУрГУ. За первые 30 дней после фактического релиза MVP привлечь не менее 60 студентов, причём не менее половины из них должны обращаться к боту каждую неделю.

## Как ведётся проект

Для учебного проекта выбрана гибридная рамка управления:

- **от PMBOK** — устав, концепция, оценка экономики, фиксированные контрольные точки и дата завершения;
- **от Agile** — недельные итерации, доска задач в GitHub Projects, приоритизированный бэклог, демонстрация результата в конце каждой итерации.

Один из технических рисков — изменение структуры сайта с расписанием. Для парсера запланированы редкие запросы и кеширование в базе. Хранение учётных данных пользователей от портала вуза не предусмотрено; возможность получения расписания без них проверяется при исследовании источника.

## Монетизация

В рамках учебного курса расписание, заметки и уведомления планируются бесплатными. Подписка за 59 ₽ в месяц — гипотеза коммерческого развития после курса, используемая в экономическом расчёте, а не действующий тариф. Оплата, проверка подписки и напоминания по дедлайнам не входят в текущий план реализации.

В принятой расчётной модели проект в рамках одного вуза не окупается, поэтому учебная версия рассматривается как некоммерческая. Решение о платных функциях и подключении других вузов потребует проверки спроса после релиза.
