# Исследование источника расписания — WBS 2.1.3 / #13

Дата проверки: **12 ноября 2026 года**. Задача: [#13](https://github.com/unlaesh/project/issues/13), требование NFR-4, описание [Feature-Parser](https://github.com/unlaesh/project/wiki/Feature-Parser).

Результат исследования: найден публичный HTML-каталог групп и расписание на `new.susu.ru`. Для наблюдённой страницы достаточно обычного HTTPS GET без учётных данных и без исполнения JavaScript. Этот источник выбран как **предпочтительный кандидат для разработки**, но получение полного четырёхнедельного горизонта пока не подтверждено. Парсер, синхронизация БД и автоматическое обновление в этой задаче не реализованы.

## Проверенные источники

Все запросы выполнялись без `Authorization`, переданных cookies, клиентских сертификатов и сессии браузера. Проверка TLS не отключалась. Точные время начала/окончания запросов, HTTP-статусы, размеры и SHA-256 ответов находятся в [метаданных](fixtures/source-research-metadata.json).

| Назначение | Проверенный URL | Наблюдение |
| --- | --- | --- |
| Каталог подразделений | <https://new.susu.ru/students/schedules> | HTTP 200; 19 ссылок на подразделения в основном содержимом |
| Каталог выбранного института | <https://new.susu.ru/students/schedules/859> | HTTP 200; 95 ссылок на группы, включая ЕТ-143 |
| Расписание выбранной группы | <https://new.susu.ru/students/schedules/859/group/2905> | HTTP 200; 62 записи занятий, 12 дат: 09–14 и 16–21 ноября 2026 года |
| Ограничения для роботов | <https://new.susu.ru/robots.txt> | HTTP 200; `User-agent: *` и пустой `Disallow`. Это наблюдение на дату проверки, а не гарантия дальнейшего доступа или разрешение на неограниченную нагрузку |
| Документация личного кабинета | <https://www.univeris.susu.ru/page_data/personal-area/personal-area-student/> | Описывает вход по логину и паролю и раздел расписания внутри личного кабинета |

`new.susu.ru` находится в домене университета. В его подвале указаны название ЮУрГУ, адрес и контакты, совпадающие с проверенной [главной страницей университета](https://www.susu.ru/ru/); есть ссылка на `www.susu.ru`. Статус этого поддомена как окончательной замены основного сайта не установлен. При использовании данных сохраняется ссылка на [сайт ЮУрГУ](https://www.susu.ru/).

Ранее предполагавшийся `online.susu.ru` — другой интерфейс. Его начальный ответ содержит оболочку приложения, а не занятия. В просмотренном публичном JavaScript маршрут `/schedule` проходит проверку входа; это согласуется с официальной инструкцией личного кабинета. Поэтому этот маршрут не выбран для загрузки без учётных данных. Наличие или отсутствие всех иных публичных API этого сервиса не установлено; защищённые методы не вызывались, учётные данные студентов не использовались.

## Группа, даты и поля

Маршрут получения идентификатора воспроизводится по ссылкам: каталог подразделений → «Институт естественных и точных наук» (`859`) → «ЕТ-143» (`2905`). Название группы находится в `.study-group__number` внутри ссылки `a.study-group__item`; числовые идентификаторы берутся из её `href`. Их нельзя получать арифметически из названия группы. На странице расписания название повторяется в `main .title-h1`.

Поля ниже относятся к фактически полученному HTML, а не к предполагаемому API:

| Поле | CSS-селектор относительно записи или дня | Правило чтения |
| --- | --- | --- |
| День | `.schedule-group__day` | Контейнер одной явно указанной даты |
| Дата | `.schedule-group__date_day` | Формат `DD.MM.YYYY`, например `12.11.2026` |
| День недели | `.schedule-group__date_week` | Дополнительная проверка даты, не источник вычисления даты |
| Запись занятия | `.schedule-group__pair` | Каждая запись обрабатывается отдельно |
| Номер пары | `.schedule-group__time_pair` | Например, `1 пара` |
| Время | `.schedule-group__time_period` | Например, `08:00 - 09:35`; начало и конец разбираются отдельно |
| Дисциплина | `.schedule-group__name` | Текст без внешних пробелов |
| Вид занятия | `.schedule-group__type` | Допускается пустое значение: в полном ответе таких записей 4 |
| Преподаватель | `.schedule-group__professor` | В образце ФИО заменены псевдонимами |
| Аудитория | `.schedule-group__room` | Сохранять строку целиком, включая корпус и буквы |
| Подгруппа | `.schedule-group__group` | В исследованном ответе пусто у всех 62 записей; номер подгруппы не придумывается |

Одинаковая дата, время и дисциплина могут встречаться в нескольких записях с разными преподавателями и аудиториями. Такие записи нельзя автоматически объединять по тройке «группа + дата + номер пары». В сохранённом примере оставлены две реальные параллельные записи иностранного языка.

В ответе один контейнер `.schedule-group__week` содержит даты сразу двух недель. Границы календарных недель нужно определять по датам, а не по имени CSS-класса. Дату занятия получаем непосредственно из `DD.MM.YYYY`; не восстанавливаем её по чётности недели, названию дня или дате скачивания.

Часовой пояс проекта — **`Asia/Yekaterinburg`**. На дату проверки это UTC+05:00. В исследованном HTML часовой пояс явно не указан: его применение является существующим правилом проекта, а не найденным полем источника. Наблюдение расписания завершено `2026-11-12T17:59:46.161064+00:00`, то есть 12 ноября в 22:59:46 по времени проекта. На странице есть занятия текущего дня, однако дата публикации/последнего изменения расписания не найдена. Время получения ответа не доказывает время обновления данных университетом.

## Недели и открытая зависимость SRC-4W

В полученном `main` нет переключателя недели, формы выбора даты или ссылки с параметром недели. Запрос без параметров возвращает даты двух учебных недель; переход между ними состоит в чтении последующих блоков дней того же ответа. JavaScript сайта при этой проверке не исполнялся. Публичный способ запросить произвольную неделю **не подтверждён**. Из этого не следует, что такого способа нет на всём сайте. Непроверенные параметры `week`, `date` и адреса API не выдаются за работающие.

Контракт [Feature-Parser](https://github.com/unlaesh/project/wiki/Feature-Parser), сценарий UC-06 и WBS 3.1.2 ([#21](https://github.com/unlaesh/project/issues/21)) требуют четыре календарные недели. Это детализация загрузки расписания FR-6; FR-4 определяет отображаемые поля пары и не задаёт горизонт. Для даты исследования это **9 ноября — 6 декабря 2026 года**. В ответе подтверждены занятия только до 21 ноября; недели с 23 и 30 ноября не представлены. Отсутствующие воскресенья и более поздние даты нельзя трактовать как подтверждённое отсутствие занятий. Повторять найденную неделю для заполнения четырёх недель также нельзя.

**SRC-4W блокирует подтверждение полноты загрузки #21**, а не получение уже опубликованного HTML. До приёмки четырёхнедельного парсера необходимо одно из решений:

1. Найти и проверить публичную навигацию по неделям либо официальный публичный экспорт с нужными датами.
2. Получить у университета публичный экспорт, не требующий учётных данных студентов.
3. Если такой источник недоступен, отдельно согласовать изменение продуктового горизонта и обновить контракт Feature-Parser, сценарий UC-06 и критерии карточек. Это только предложенный вариант; в данном исследовании требование четырёх недель **не изменено**.

Публичный `new.susu.ru` позволяет продолжить работу над справочником групп и разбором доступных записей. Он пока не доказывает полное выполнение требования к горизонту. При недоступности источника будущая реализация должна сохранять ранее загруженные данные и отмечать неполноту/ошибку, а не создавать пустое успешное обновление. Планируемые в Feature-Parser ограничения частоты запросов сохраняются; контракт стабильности HTML и SLA источника не установлены.

## Образец и проверка

[schedule-example.html](fixtures/schedule-example.html) — небольшой обезличенный фрагмент **реального ответа**, а не вручную сочинённое расписание. Сохранены 5 из 62 записей на четырёх датах: параллельные занятия, обычная лекция, занятие с пустым видом и занятие следующей недели. Название публичной группы, даты, время, дисциплины, виды и аудитории сохранены; ФИО заменены на `Преподаватель 01`–`05`. Таблица соответствия ФИО псевдонимам не сохраняется.

Оболочка сайта, ресурсы, скрипты, ссылки и остальные занятия удалены; добавлены самостоятельная HTML-оболочка и комментарий о происхождении. Классы и вложенность выбранных узлов сохранены, пробелы нормализованы. Это исторический тестовый образец, не источник актуального расписания. Исходный полный ответ с ФИО в репозиторий не включён; его SHA-256 записан в метаданных для идентификации снимка.

При подготовке проверено:

- все пять записей совпадают с выбранными узлами исходного ответа по дате, времени, дисциплине, виду, аудитории и пустой подгруппе;
- сохранены две записи одного временного интервала и один пустой вид занятия;
- ни одно исходное ФИО преподавателя не осталось в образце;
- нет скриптов, форм, изображений, внешних ресурсов, обработчиков событий и данных авторизации;
- SHA-256 и ожидаемые значения пяти записей записаны в JSON.

Для повторной ручной проверки публичного источника из корня репозитория:

```bash
curl --fail --location --max-time 30 --silent --show-error \
  'https://new.susu.ru/students/schedules/859/group/2905' \
  --output /tmp/pary-schedule-public.html \
  --write-out 'HTTP %{http_code}\n'
```

Ответ динамический: позднее даты и его SHA-256 могут отличаться. Новый полный ответ не следует автоматически добавлять в Git без обезличивания. Проверка целостности сохранённого образца не требует сети или сторонних пакетов:

```bash
python3 - <<'PY'
import hashlib
import json
from pathlib import Path

metadata = json.loads(Path('docs/fixtures/source-research-metadata.json').read_text())
fixture = Path(metadata['fixture']['path']).read_bytes()
assert hashlib.sha256(fixture).hexdigest() == metadata['fixture']['sha256']
assert len(metadata['fixture']['expected_records']) == 5
print('Образец соответствует зафиксированному SHA-256; ожидается 5 записей.')
PY
```
