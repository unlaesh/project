# ЮУрГУ.Пары

Учебный проект Telegram-бота с расписанием пар для студентов ЮУрГУ. Планируемые функции: просмотр расписания, заметки к занятиям и напоминания о следующей паре.

> **Статус:** реализованы HTTP-каркас и компонент навигации Telegram; регистрация, расписание и транспорт бота ещё в разработке.
> **Начало учебного проекта:** 21.09.2026.
> **План оставшейся работы:** 12.11.2026 – 15.12.2026; срок готовности — 15 декабря.

## Зачем

Проект решает потребность студента быстро узнать следующую пару и аудиторию в привычном мессенджере, а также хранить домашние задания рядом с расписанием. Исходный сценарий — открыть расписание на online.susu.ru и найти нужный день; результат проверки доступа и публичная альтернатива описаны в [исследовании источника](docs/source-research-step12.md).

Планируемое решение переносит просмотр расписания в Telegram: заметки будут привязаны к конкретной паре, а напоминания помогут заранее подготовиться к занятию.

## Планируемые возможности

После реализации пользователь сможет указать свою группу и пользоваться следующими функциями:

| Возможность | Этап |
| --- | --- |
| Расписание на сегодня, завтра и неделю одной командой: название пары, время, аудитория, преподаватель | MVP |
| Текстовые заметки к парам (домашнее задание, записанные текстом дедлайны), видимые вместе с расписанием | релиз 1.1 |
| Уведомление о следующей паре и аудитории за выбранное время до начала | релиз 1.2 |
| Уведомления об изменениях в расписании | релиз 1.2 |

В учебной версии все перечисленные функции бесплатны. Автоматические напоминания по дедлайнам — идея дальнейшего развития, не входящая в требования релиза 1.2.

Роли в системе:

| Роль | Что делает |
| --- | --- |
| Пользователь | Смотрит расписание, ведёт заметки к парам, настраивает уведомления |
| Администратор | Просматривает пользователей |
| Сервис | Парсит расписание с сайта ЮУрГУ |

## Технологии

В текущем коде используются Python 3.12+, FastAPI, Uvicorn, Pydantic Settings и aiogram 3 для навигационного компонента; для проверок — Pytest, HTTPX и Ruff.

Целевой стек остальных компонентов:

| Задача | Технология |
| --- | --- |
| Транспорт и прикладные сценарии Telegram | FastAPI + aiogram; навигационный компонент уже реализован |
| База данных | PostgreSQL |
| Миграции базы данных | Alembic |
| Парсинг расписания | Playwright, BeautifulSoup |
| Развёртывание | Docker Compose, Nginx, VPS |

Компонент навигации не включает остальные прикладные сервисы из таблицы. Согласно [целевой архитектуре](https://github.com/unlaesh/project/wiki/Architecture), обмен данными между сервисами будет идти через PostgreSQL; брокер сообщений не предусмотрен.

## Запуск текущего HTTP-каркаса

Нужен Python 3.12 или новее.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env          # локальные настройки; .env не коммитится

python -m pary.api            # HTTP-сервис на http://127.0.0.1:8000
curl http://127.0.0.1:8000/health
```

Для `/health` токен Telegram и база данных не нужны. Команда запускает HTTP-сервис; вебхук и получение обновлений Telegram ещё не подключены. Навигационный router проверяется отдельно, без токена и сети.

## Компонент навигации Telegram

`pary.bot.MenuHandlers` принимает четыре готовых асинхронных обработчика разделов. `create_menu_router(handlers)` передаёт им нажатия кнопок; `show_main_menu(message, handlers=handlers)` вызывается после проверки регистрации. Вложенный обработчик добавляет `back_to_menu_keyboard()` к ответу. Возврат в главное меню отменяет незавершённый диалог и очищает его FSM-состояние, сохраняя бизнес-данные в области ответственности соответствующего сервиса.

Заметки включаются только передачей готового `notes`-обработчика. `/start`, неизвестный текст и команды остаются другим router; модуль не подменяет регистрацию, загрузку расписания или настройки. Это компонент для последующего подключения, а не запущенный Telegram-бот.

```bash
pytest tests/test_bot_navigation.py
```

Проверки CI (GitHub Actions) настроены для push в любую ветку и pull request в `main`:

```bash
ruff check .
ruff format --check .
pytest
```

## Цель проекта

К 15 декабря 2026 года выпустить обязательный MVP Telegram-бота с выбором группы и просмотром расписания ЮУрГУ. За первые 30 дней после фактического релиза MVP привлечь не менее 60 студентов, причём не менее половины из них должны обращаться к боту каждую неделю.

## Как ведётся проект

Для учебного проекта выбрана гибридная рамка управления:

- **от PMBOK** — устав, концепция, оценка экономики, фиксированные контрольные точки и дата завершения;
- **от Agile** — недельные итерации, доска задач в GitHub Projects, приоритизированный бэклог, демонстрация результата в конце каждой итерации.

Один из технических рисков — изменение структуры сайта с расписанием. Для парсера запланированы редкие запросы и кеширование в базе. Хранение учётных данных пользователей от портала вуза не предусмотрено; наблюдённый публичный источник и непроверенные условия его использования описаны в исследовании #13.

## Монетизация

В рамках учебного курса расписание, заметки и уведомления планируются бесплатными. Подписка за 59 ₽ в месяц — гипотеза коммерческого развития после курса, используемая в экономическом расчёте, а не действующий тариф. Оплата, проверка подписки и напоминания по дедлайнам не входят в текущий план реализации.

В принятой расчётной модели проект в рамках одного вуза не окупается, поэтому учебная версия рассматривается как некоммерческая. Решение о платных функциях и подключении других вузов потребует проверки спроса после релиза.
